# Contributing

Use branches and open pull requests for changes.

Guidelines:

- keep changes scoped to one purpose;
- do not include unrelated formatting churn;
- follow the existing WordPress and project conventions;
- add or update tests when the project already has a test setup;
- keep Free and Pro code separated;
- do not change versions, slugs, namespaces, text domains, headers, licenses, or commercial names without approval;
- do not commit secrets, local configuration, customer data, logs, database dumps, generated ZIP files, or backups.

Before opening a pull request, run the available local checks and document what was tested.
